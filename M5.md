# M5 — Supply Engine Implementation

## Overview
Implement the supply distribution system with deterministic micro-ordering, validation rules, and phase transitions. This milestone focuses on `DistributeSupplyAction` with territory-based ordering and proper supply exhaustion handling.

## Goals
- Implement `DistributeSupplyAction` with deterministic micro-order (by territory ID)
- Enforce v5 validation: zero values rejected, sum rules, ownership checks
- Implement supply exhaustion and early-end legality
- Handle phase transitions from SUPPLY back to ATTACK or next player
- Maintain tick-per-die placement for deterministic progression

## Architecture

### Supply System Design
```python
# Supply placement follows deterministic micro-order:
# 1. Sort placements by territory_id ascending
# 2. Place dice one at a time in order  
# 3. Each die placement advances tick by 1
# 4. Final placement triggers phase/turn transition (no extra tick)
```

### Supply Validation Rules (v5)
- **Zero values rejected**: `placements` cannot contain zero values
- **Ownership required**: All territories must be owned by current player
- **Capacity limits**: Respect max dice per territory (if configured)
- **Sum constraints**: Total dice distributed ≤ available supply
- **Early end legality**: Player can distribute less than full supply

## Deliverables

### 1. Supply Actions (`core/actions.py`)
- **`ActionValidator.validate_supply()`**: Complete supply validation
- **`ActionExecutor.execute_supply()`**: Deterministic supply distribution  
- **Supply micro-step logic**: One die at a time, deterministic order

### 2. Supply Phase Logic (`core/engine.py`)
- **Supply calculation**: Determine available dice for current player
- **Phase transitions**: SUPPLY → ATTACK or next player turn
- **`_generate_valid_actions()` during SUPPLY**: Only `EndTurnAction` (no supply actions enumerated)

### 3. Enhanced State Management (`core/state.py`)
- **Supply tracking**: Available supply per player per turn
- **Supply exhaustion**: Track when player has distributed all available dice
- **Phase transition rules**: SUPPLY → ATTACK when supply complete

### 4. Error Handling (`api/types.py`)
- **Enhanced `InvalidAction` codes**: Supply-specific validation errors
- **`error_data` fields**: Machine-readable supply violation details
- **Supply validation error context**: Invalid territories, amounts, etc.

## Implementation Tasks

### Phase 1: Supply Calculation & Validation

1. **Implement supply calculation in `core/engine.py`**:
   ```python
   def _calculate_available_supply(self, player_id: int) -> int:
       """Calculate supply dice available for player this turn."""
       owned_territories = sum(1 for owner in self.state.owners if owner == player_id)
       
       # Basic supply: floor(territories / 3), minimum 3
       base_supply = max(3, owned_territories // 3)
       
       # Additional supply from connected regions (future enhancement)
       # For M5: use base supply only
       return base_supply
   ```

2. **Implement `validate_supply()` in `core/actions.py`**:
   ```python
   def validate_supply(self, action: DistributeSupplyAction, player_id: int) -> Optional[str]:
       """Validate supply distribution action."""
       
       # v5: Reject zero values
       if any(amount <= 0 for amount in action.placements.values()):
           return "INVALID_SUPPLY_ZERO_VALUES"
           
       # Check territory ownership
       invalid_territories = []
       for territory_id in action.placements.keys():
           if self.state.owners[territory_id] != player_id:
               invalid_territories.append(territory_id)
       
       if invalid_territories:
           return "INVALID_SUPPLY_NOT_OWNED"
           
       # Check supply limits
       available_supply = self._calculate_available_supply(player_id)
       total_requested = sum(action.placements.values())
       
       if total_requested > available_supply:
           return "INVALID_SUPPLY_INSUFFICIENT"
           
       # Check capacity limits (if configured)
       for territory_id, amount in action.placements.items():
           current_dice = self.state.dice[territory_id]
           if current_dice + amount > self.config.max_dice_per_territory:
               return "INVALID_SUPPLY_CAPACITY_EXCEEDED"
               
       return None  # Valid
   ```

### Phase 2: Deterministic Supply Distribution

3. **Implement `execute_supply()` in `core/actions.py`**:
   ```python
   def execute_supply(self, action: DistributeSupplyAction, player_id: int) -> ActionResult:
       """Execute supply distribution with deterministic micro-order."""
       
       # Sort placements by territory_id for deterministic order
       sorted_placements = sorted(action.placements.items())
       
       new_state = copy.deepcopy(self.state)
       
       # Place dice one at a time, advancing tick for each
       for territory_id, amount in sorted_placements:
           for _ in range(amount):
               new_state.dice[territory_id] += 1
               new_state.advance_tick()  # Tick per die
       
       # Check if supply exhausted or early end
       remaining_supply = self._calculate_available_supply(player_id) - sum(action.placements.values())
       
       if remaining_supply == 0 or action.early_end:
           # Transition to next phase/player (no extra tick)
           new_state = self._complete_supply_phase(new_state)
           
       return ActionResult(
           success=True,
           new_game_state=new_state.to_public_state(),
           tick_id=str(new_state.tick_id),
           state_hash=new_state.get_state_hash(),
           position_hash=new_state.get_position_hash()
       )
   ```

4. **Implement `_complete_supply_phase()`**:
   ```python
   def _complete_supply_phase(self, state: CoreState) -> CoreState:
       """Complete supply phase and transition to next state."""
       
       # Check if same player can continue attacking
       if self._player_can_attack(state.active_player_id):
           state.phase = GamePhase.ATTACK
       else:
           # Move to next player's turn
           state.advance_turn()  # This handles player rotation and phase setting
           
       return state
   ```

   def _generate_valid_actions(self) -> List[Action]:

6. **Update phase transition logic**:
   ```python
   def _should_enter_supply_phase(self) -> bool:
       """Determine if player should enter SUPPLY after attacks."""
       
       # Enter supply if player has available supply and owns territories
       available_supply = self._calculate_available_supply(self.state.active_player_id)
       owns_territories = any(owner == self.state.active_player_id for owner in self.state.owners)
       
       return available_supply > 0 and owns_territories
   ```

### Phase 4: Error Handling & Validation

7. **Enhance error handling with `error_data`**:
   ```python
   def _create_supply_error_result(self, error_code: str, action: DistributeSupplyAction) -> ActionResult:
       """Create error result with detailed error_data."""
       
       error_data = {}
       
       if error_code == "INVALID_SUPPLY_NOT_OWNED":
           invalid_territories = [
               tid for tid in action.placements.keys() 
               if self.state.owners[tid] != self.state.active_player_id
           ]
           error_data = {"invalid_territories": invalid_territories}
           
       elif error_code == "INVALID_SUPPLY_ZERO_VALUES":
           zero_territories = [
               tid for tid, amount in action.placements.items() 
               if amount <= 0
           ]
           error_data = {"zero_value_territories": zero_territories}
           
       return ActionResult(
           success=False,
           error_code=error_code,
           error_data=error_data,
           new_game_state=self.state.to_public_state(),  # Unchanged
           tick_id=str(self.state.tick_id),
           state_hash=self.state.get_state_hash(),
           position_hash=self.state.get_position_hash()
       )
   ```
